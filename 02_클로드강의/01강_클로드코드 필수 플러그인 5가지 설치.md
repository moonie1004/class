# 클로드코드 필수 플러그인 5가지 설치

| 구분 | 내용 |
| --- | --- |
| 일시 | ____년 __월 __일( ) ____:____ ~ ____:____ |
| 강사 | 성문희 |
| 참가자 | |
| 실습 준비 | 노트북, Node.js 20 이상, (선택) Docker Desktop |

### 오늘의 한 줄

클로드코드를 '코드만 짜는 도구'에서 '직접 확인하고, 데이터베이스를 만지고, 보안까지 점검하는 도구'로 바꾸는 다섯 가지를 오늘 다 설치합니다. 전부 깔아도 30~40분입니다.

### 오늘 끝나면 이걸 할 수 있습니다

- 다섯 가지 도구가 각각 무엇을 대신해 주는지 한 줄로 설명할 수 있다
- 내 노트북에 Node.js 환경을 확인하고 전역 설치를 직접 할 수 있다
- Playwright CLI로 AI가 브라우저를 열어 결과를 검증하게 만들 수 있다
- Supabase 플러그인으로 채팅 한 줄에 DB 컬럼을 추가할 수 있다
- Strix를 합법적인 범위 안에서만 쓰는 기준을 안다
- 설치가 안 될 때 어디를 먼저 확인할지 안다

> 이 문서의 설치 명령어는 2026년 9월 기준으로 공식 문서에서 확인한 것입니다. 배포 자료의 원문과 달라진 부분은 문서 아래쪽 '원문에서 바로잡은 내용'에 따로 정리했습니다.

## 시작 전에 — 사전 준비물

| 준비물 | 확인 방법 | 없으면 |
| --- | --- | --- |
| Node.js **20 이상** | 터미널에 `node -v` | [nodejs.org](https://nodejs.org)에서 LTS 버전 설치 |
| Docker Desktop (Strix 전용) | Docker Desktop 실행 중인지 확인 | [docker.com](https://www.docker.com)에서 설치 |
| 터미널 | Windows는 PowerShell, Mac은 터미널 | — |

Strix를 안 쓸 거라면 Docker는 건너뛰어도 됩니다.

## 한눈에 보기

| # | 도구 | 한 줄 정의 | 설치 한 줄 | 언제 쓰나 |
| --- | --- | --- | --- | --- |
| 1 | **Playwright CLI** | AI가 진짜 브라우저를 열어 직접 확인 | `npm install -g @playwright/cli@latest` | 만든 화면이 실제로 되는지 검증할 때 |
| 2 | **Supabase Plugin** | 채팅으로 DB 테이블·컬럼 조작 | `npx plugins add supabase-community/supabase-plugin` | Supabase로 백엔드를 쓸 때 |
| 3 | **Strix** | AI가 해커처럼 내 앱을 공격해 취약점 발견 | `curl -sSL https://strix.ai/install \| bash` | 배포 전 보안 점검 |
| 4 | **Skill UI** | 웹사이트 색·폰트·여백을 통째로 추출 | `npm install -g skillui` | "이 사이트처럼 만들어줘"를 정확하게 |
| 5 | **Context7** | 라이브러리 최신 공식 문서를 실시간 주입 | `npx ctx7 setup` | 옛날 문법으로 코드가 나올 때 |

### 설치 순서 추천

- ⬜ 1단계 — Node 버전 확인 (`node -v` → 20 이상)
- ⬜ 2단계 — Context7 설치 (가장 쉽고 효과 체감이 빠름)
- ⬜ 3단계 — Playwright CLI 설치
- ⬜ 4단계 — Skill UI 설치 (디자인 작업이 있을 때)
- ⬜ 5단계 — Supabase Plugin 설치 (Supabase 쓰는 경우만)
- ⬜ 6단계 — Strix 설치 (Docker 준비된 뒤에)

## 1. Playwright CLI — AI가 직접 눈으로 확인하게

[github.com/microsoft/playwright-cli](https://github.com/microsoft/playwright-cli) · 공식 문서 [playwright.dev/agent-cli](https://playwright.dev/agent-cli/installation)

### 이게 뭔가요

마이크로소프트가 만든 도구입니다. AI가 진짜 웹 브라우저를 열어서 사람처럼 클릭·타이핑·스크롤할 수 있게 해줍니다.

### 뭘 할 수 있나요

- 브라우저를 열고 특정 페이지로 이동
- 버튼 클릭, 폼 입력, 스크롤
- 화면 스크린샷 촬영
- 콘솔 에러·네트워크 요청 확인 (개발자도구처럼)

### 왜 좋은가요

원래 AI는 코드만 짜고 "완료했습니다"로 끝납니다. 그 페이지를 실제로 열어본 적이 없습니다. 이 도구가 있으면 AI가 직접 보고 확인합니다 — 버튼이 짤렸는지, 링크가 죽었는지를 AI가 스스로 발견합니다.

### 설치 방법

| 순서 | 명령어 | 설명 |
| --- | --- | --- |
| 1 | `node -v` | **20 이상**이어야 합니다 (18로는 안 됩니다) |
| 2 | `npm install -g @playwright/cli@latest` | 1분 내로 설치 완료 |
| 3 | `playwright-cli install --skills` | 클로드코드가 이 도구를 인식하게 하는 **필수 단계** |
| 4 | `playwright-cli --help` | 설치된 스킬 경로가 출력되면 성공 |

브라우저는 첫 사용 시 자동으로 내려받습니다. 미리 받아두려면 `playwright-cli install-browser`를 실행하면 됩니다.

### 사용법

```
playwright-cli 써서 localhost:3000 열고 "무료로 시작하기" 버튼 눌러봐.
제대로 이동하는지 확인해줘.
```

→ AI가 브라우저를 열고, 버튼을 찾고, 클릭하고, 스크린샷을 찍어서 "정상 이동했습니다" 또는 "404 떴어요"라고 직접 확인한 결과를 알려줍니다.

> ❗ `@playwright/test`(테스트 러너)와 헷갈리지 마세요. 설치할 패키지는 `@playwright/cli`입니다.

## 2. Supabase Plugin — 채팅으로 데이터베이스 조작

[supabase.com/docs/guides/ai-tools/plugins](https://supabase.com/docs/guides/ai-tools/plugins)

### 이게 뭔가요

Supabase(요즘 많이 쓰는 데이터베이스·백엔드 서비스) 공식 플러그인입니다. 클로드코드 안에서 Supabase를 바로 조작할 수 있게 해줍니다.

### 뭘 할 수 있나요

- 데이터베이스 테이블 조회·생성·수정
- 컬럼 추가·삭제 같은 구조 변경(마이그레이션)
- 서버 함수(Edge Function) 배포
- Supabase·PostgreSQL 권장 방식대로 자동 설정

### 왜 좋은가요

원래는 Supabase 웹사이트 로그인 → 프로젝트 찾기 → Table Editor → 테이블 찾기 → 컬럼 추가 → 타입 선택까지 최소 6번 클릭입니다. 이제 채팅창에 한 문장이면 끝납니다.

### 설치 방법

**방법 A — 한 줄 설치 (권장)**

```
npx plugins add supabase-community/supabase-plugin
```

**방법 B — 수동 설치**

| 순서 | 명령어 | 설명 |
| --- | --- | --- |
| 1 | `claude plugin marketplace add anthropics/claude-plugins-official` | 앤트로픽 공식 플러그인 저장소 등록 |
| 2 | `claude plugin install supabase@claude-plugins-official` | Supabase 플러그인 설치 |

**공통 마무리**

| 순서 | 할 일 | 설명 |
| --- | --- | --- |
| 3 | 클로드코드에서 `/reload-plugins` | 이걸 빼먹으면 설치돼도 꺼진 상태로 남습니다 |
| 4 | 첫 사용 시 브라우저 로그인 | 본인 Supabase 계정으로 인증하면 그때부터 본인 프로젝트에 접근됩니다 |

### 사용법

```
user 테이블에 email_verified 컬럼 추가해줘. boolean이고 기본값은 false로.
```

→ 클로드코드가 뒤에서 `ALTER TABLE users ADD COLUMN email_verified boolean DEFAULT false;`를 실행합니다. Supabase 대시보드를 새로고침하면 클릭 한 번 안 했는데 컬럼이 생겨 있습니다.

## 3. Strix — AI가 해커처럼 내 앱을 공격

[github.com/usestrix/strix](https://github.com/usestrix/strix)

### 이게 뭔가요

오픈소스 AI 침투테스트(모의해킹) 도구입니다. AI가 실제 해커처럼 내 웹사이트나 코드를 직접 공격해봅니다.

### 뭘 할 수 있나요

- SQL 인젝션, XSS, 인증 우회, 권한 문제(IDOR) 등 실제 취약점 유형 스캔
- 단순 경고가 아니라 실제로 뚫어보고 증명
- 심각도별(Critical / High / Medium) 리포트 생성
- 발견된 문제의 수정 패치까지 생성

### 왜 좋은가요

보안 전문가를 고용하면 몇 주가 걸리고 비용도 큽니다. Strix는 몇 시간 안에 끝나고, 배포 전에 미리 구멍을 찾아줍니다.

### 설치 방법

| 순서 | 명령어 | 설명 |
| --- | --- | --- |
| 1 | Docker Desktop 실행 | 반드시 실행 중이어야 합니다 |
| 2 | `curl -sSL https://strix.ai/install \| bash` | 자동 설치 |
| 3 | `export STRIX_LLM="제공자/모델ID"` | 공격 분석에 쓸 AI 모델 지정 (공식 문서 예시: `openai/gpt-5.4`) |
| 4 | `export LLM_API_KEY="본인 API 키"` | 해당 제공자의 API 키 |
| 5 | `strix --target ./내프로젝트폴더` | 첫 실행 시 Docker 이미지 자동 다운로드 |

> ❗ `STRIX_LLM`에는 **현재 실제로 존재하는 모델 ID**를 넣어야 합니다. 형식은 `제공자/모델ID`이고, Anthropic 모델을 쓰려면 `anthropic/<현재 모델 ID>` 형태로 적습니다. 모델 이름은 자주 바뀌니 사용하는 제공자의 문서에서 최신 ID를 확인하세요 — 없는 ID를 넣으면 실행 시 에러가 납니다.

### 사용법

```
strix --target ./내프로젝트폴더          # 로컬 코드 스캔
strix --target https://github.com/org/repo   # GitHub 저장소 점검
strix --target https://내사이트.com          # 실제 웹앱 점검
strix -n --target https://내사이트.com       # 헤드리스 모드 (CI/CD용)
strix view                                   # 최근 실행 결과 보기
```

실행하면 이런 식으로 진행됩니다.

```
[1/5] 코드 정찰 중... 라우트 12개, API 엔드포인트 8개 발견
[2/5] SQL Injection 시도 → /api/login ... 차단됨
[3/5] IDOR 테스트 → /api/orders/:id ... 취약점 발견 ⚠
[4/5] 하드코딩된 시크릿 스캔 → /static/main.js ... API 키 노출 발견 ⚠
[5/5] 리포트 생성 완료
```

> ⚠️ **반드시 본인 소유이거나 서면으로 테스트 허락을 받은 대상에만 사용하세요.** 남의 사이트를 무단으로 점검하면 대부분의 국가에서 불법이며, 모든 법적 책임은 실행한 사람에게 있습니다. 공식 문서도 같은 조건을 명시하고 있습니다.

## 4. Skill UI — 사이트의 디자인을 통째로 추출

[github.com/amaancoderx/npxskillui](https://github.com/amaancoderx/npxskillui)

### 이게 뭔가요

어떤 웹사이트든 URL만 넣으면 색상·폰트·여백 스타일을 통째로 분석해 뽑아주는 도구입니다. AI 추측이 아니라 실제 코드를 뜯어보는 방식이라 정확합니다.

### 뭘 할 수 있나요

- 정확한 색상 코드, 폰트 이름, 여백 크기 추출
- (Ultra 모드) 스크롤 화면 캡처, 애니메이션 감지, 버튼·카드 스타일 분석
- 클로드코드가 자동으로 읽는 파일(`SKILL.md`)로 저장

### 왜 좋은가요

"이 사이트처럼 예쁘게 만들어줘"라고 말로만 시키면 AI는 기억으로 대충 흉내만 냅니다. 이 도구를 쓰면 진짜 색상 코드와 폰트를 넣고 만들게 되니 결과가 훨씬 정교해집니다.

### 설치 방법

| 순서 | 명령어 | 설명 |
| --- | --- | --- |
| 1 | `npm install -g skillui` | 색상·폰트·여백 추출만 필요하면 이 한 줄로 끝 (Node 18 이상) |
| 2 (선택) | `npm install playwright` → `npx playwright install chromium` | 스크롤 캡처·애니메이션 분석(Ultra 모드)을 쓸 때만 |
| 3 | `skillui --url https://분석할사이트` | 몇 초~몇 분 안에 결과 폴더 생성 |

### 생성되는 파일

| 파일 | 내용 |
| --- | --- |
| `SKILL.md` | 클로드코드가 자동으로 읽는 마스터 파일 |
| `DESIGN.md` | 디자인 시스템 토큰 전체 |
| `CLAUDE.md` | 프로젝트 컨텍스트 |
| `tokens/` | colors.json, spacing.json, typography.json |
| `screens/` · `references/` | 스크린샷, 애니메이션·레이아웃·컴포넌트 정리 |

### 사용법

```
skillui --url https://linear.app                 # 기본 분석
skillui --url https://linear.app --mode ultra    # 캡처·애니메이션까지
skillui --dir ./my-app                           # 내 프로젝트 분석
```

분석이 끝나면 그 폴더에서 클로드코드를 열고 이렇게 말합니다.

```
cd linear-design && claude
```

```
이 디자인 시스템 그대로 써서 회사 소개 랜딩페이지 만들어줘
```

→ 클로드코드가 `SKILL.md`를 자동으로 읽고 추출된 정확한 색상·폰트 값으로 페이지를 만듭니다.

> ❗ 남의 사이트 디자인을 추출하는 도구인 만큼, 결과물을 그대로 베껴 쓰면 저작권·상표 문제가 될 수 있습니다. 색상·간격 같은 스타일 참고용으로 쓰고, 로고·문구·이미지는 직접 만든 것을 넣으세요.

## 5. Context7 — 최신 공식 문서를 실시간으로 주입

[github.com/upstash/context7](https://github.com/upstash/context7) · [context7.com/install](https://context7.com/install)

### 이게 뭔가요

AI에게 특정 라이브러리의 실시간 최신 공식 문서를 넣어주는 도구입니다. AI는 학습 시점까지의 지식만 알기 때문에, 이게 없으면 옛날 문법으로 답할 수 있습니다.

### 뭘 할 수 있나요

- 질문할 때마다 라이브러리의 최신 문서를 실시간으로 가져와 AI에게 전달
- 특정 버전 지정 가능 (예: "Next.js 14 기준으로")

### 왜 좋은가요

"AI가 옛날 문법으로 코드를 짬 → 실행하면 에러 → 원인 찾느라 시간 낭비" 이 고리가 크게 줄어듭니다.

### 설치 방법

| 순서 | 할 일 | 설명 |
| --- | --- | --- |
| 1 | `npx ctx7 setup` | 설치와 설정이 한 번에 진행됩니다 |
| 2 | 브라우저 로그인 | 자동으로 창이 열립니다. 로그인하면 API 키가 발급됩니다 |
| 3 | 사용할 도구 선택 | 목록이 뜨면 **Claude Code** 선택 |
| 4 (선택) | [context7.com/dashboard](https://context7.com/dashboard)에서 무료 키 발급 | 하루 사용 횟수 제한이 늘어납니다 (안 받아도 기본 사용 가능) |

### 사용법

프롬프트 끝에 `use context7`만 붙이면 됩니다.

```
Next.js 서버 액션으로 폼 제출 처리하는 코드 짜줘. use context7
```

| 구분 | Context7 없이 | Context7으로 |
| --- | --- | --- |
| 참고하는 문서 | 학습 시점까지의 기억 | 실시간 최신 공식 문서 |
| 결과 코드 | 옛날 문법(deprecated 경고 가능) | 현재 문법 |
| 실행 결과 | 에러 나서 원인 찾아야 함 | 대부분 한 번에 통과 |

---

## 원문에서 바로잡은 내용

공식 문서로 확인하면서 원문 가이드와 달랐던 부분입니다. 수강생에게 그대로 나눠주기 전에 이 부분만 반영하면 됩니다.

| 항목 | 원문 | 확인된 사실 |
| --- | --- | --- |
| Playwright CLI — Node 버전 | 18 이상 | **20 이상** (공식 설치 문서 기준) |
| Playwright CLI — 설치 확인 | `playwright-cli --version` | `playwright-cli --help`가 확실합니다. 설치된 스킬 경로가 출력되는지로 확인 |
| Supabase — 설치 | 마켓플레이스 등록 + 설치 2단계만 안내 | 공식 문서가 권장하는 **한 줄 설치**(`npx plugins add supabase-community/supabase-plugin`)가 따로 있습니다 |
| Strix — 모델 지정 | `anthropic/claude-sonnet-4-6` | 형식은 맞지만 모델 ID는 수시로 바뀝니다. 공식 예시는 `openai/gpt-5.4`이며, 쓰는 제공자의 현재 모델 ID를 확인해 넣어야 합니다 |
| Skill UI — 모드 | 기본/고급 정도만 언급 | 정식 옵션은 `--mode ultra`, `--dir`, `--repo`. 결과물도 `DESIGN.md` 외에 `SKILL.md`·`tokens/`·`screens/`가 함께 생성됩니다 |
| Strix — 실행 | `strix --target` 한 가지 | GitHub 저장소·실제 URL도 대상이 되고, `-n`(헤드리스), `strix view`(결과 다시 보기)가 있습니다 |

## 자주 막히는 지점

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| `npm: command not found` | Node.js 미설치 | nodejs.org에서 LTS 설치 후 터미널 재시작 |
| Playwright 설치는 됐는데 클로드코드가 모름 | `install --skills`를 안 함 | `playwright-cli install --skills` 실행 후 `--help`로 경로 확인 |
| Supabase 플러그인이 동작 안 함 | `/reload-plugins`를 안 함 | 클로드코드에서 `/reload-plugins` 입력 |
| Strix 첫 실행이 멈춘 듯함 | Docker 이미지 최초 다운로드 | 몇 분 기다리기. Docker Desktop 실행 여부 확인 |
| Skill UI에서 스크린샷이 안 나옴 | Playwright 미설치 | `npm install playwright` → `npx playwright install chromium` |
| 권한 오류(EACCES)로 전역 설치 실패 | 전역 폴더 권한 | Mac/Linux는 `sudo`, Windows는 관리자 권한 터미널 |
