# 사진 넣으면 블로그 글이 완성되는 자동화 툴 만들기

| 구분 | 내용 |
| --- | --- |
| 일시 | ____년 __월 __일( ) ____:____ ~ ____:____ |
| 강사 | 성문희 |
| 이름 | |
| 준비물 | 노트북(윈도우/맥), 네이버 계정, 클로드 유료 구독, 블로그에 올릴 사진 몇 장 |
| 소요 시간 | 처음 설치·제작 1시간 이내 / 그 뒤로는 글 1편에 몇 분 |

### 오늘의 한 줄

사진 몇 장을 폴더에 넣고 메모 한 줄만 쓰면, 블로그 글이 완성되고 네이버에 **임시저장**까지 됩니다. 발행 버튼만 내가 누르면 끝이에요.

### 오늘 끝나면 이걸 할 수 있습니다

- 이 툴이 무엇을 대신해 주고 무엇은 안 해 주는지 설명할 수 있다
- 노트북에 클로드 코드를 설치할 수 있다
- 프롬프트 하나를 붙여넣어 나만의 글쓰기 툴을 만들 수 있다
- 사진 + 메모 한 줄로 블로그 초안을 뽑을 수 있다
- 막혔을 때 어떻게 해결하는지 안다

## PART 1. 이게 대체 뭔가요? — 아주 쉽게

### 1-1. 지금까지 AI로 블로그 글 쓰면 왜 별로였나

챗GPT에 "블로그 글 써줘" 해 본 분들은 압니다.

- 말투가 어색하다
- 없는 사실을 지어낸다
- 딱 봐도 광고 티가 난다

결국 처음부터 다시 쓰게 되죠.

### 1-2. 오늘 하는 건 다릅니다

오늘은 **AI에게 "글 써줘"라고 부탁하는 게 아니라, 15년차 파워블로거의 일하는 방식을 통째로 컴퓨터에 설치**합니다.

> 🍳 **비유** — 매번 "김치찌개 끓여줘"라고 부탁하는 것과, 우리 집 냉장고에 맞춘 **레시피 책 한 권을 만들어 두는 것**의 차이입니다. 레시피가 있으면 매번 설명하지 않아도 늘 같은 맛이 나와요.

### 1-3. 이 툴이 해 주는 일 5가지

| # | 하는 일 | 쉽게 말하면 |
| --- | --- | --- |
| 1 | 검색하는 사람 1명을 정하고 그 사람 마음에 꽂히는 첫 문단부터 쓴다 | "누구한테 말하는 글인지" 먼저 정한다 |
| 2 | 폴더에 넣은 사진을 AI가 **직접 보고** 분석한다 | 간판, 메뉴판, 작업 장면을 눈으로 읽어냄 |
| 3 | 키워드 배치·가독성·저품질 회피를 자동 적용한다 | 네이버가 좋아하는 형식으로 자동 정리 |
| 4 | 사진에 남의 얼굴이나 차 번호판이 보이면 알려주고, 승인하면 모자이크 처리한다 | 개인정보 사고 방지 |
| 5 | 네이버 블로그에 **임시저장**까지 해 준다 | 글·사진·태그·지도·동영상·소제목 서식까지 자동 입력 |

### 1-4. 이 툴이 **안 하는** 일

- ❌ **발행은 안 합니다.** 일부러 막아 놨어요. 임시저장까지만 하고, 발행 버튼은 항상 사람이 눌러야 합니다.
- ❌ 상위노출이나 수익을 보장하지 않습니다. 꾸준히 발행하도록 도와주는 도구예요.
- ❌ 내가 정보를 안 주면 좋은 글이 안 나옵니다. (이건 PART 8에서 자세히)

## PART 2. 먼저 알아야 할 낱말 6개

강의 중에 계속 나올 말들입니다. 어렵게 들리지만 뜻은 아주 단순해요.

| 낱말 | 아주 쉬운 뜻 | 비유 |
| --- | --- | --- |
| **터미널** | 컴퓨터에 글자로 명령을 내리는 까만 창 | 마우스 대신 **글로 심부름 시키는 창구** |
| **Node.js** | 프로그램이 돌아가게 해 주는 밑바탕 프로그램. 무료 | 콘센트. 이게 있어야 다른 게 켜짐 |
| **npm** | 프로그램을 설치해 주는 심부름꾼 | 앱스토어의 '설치' 버튼 |
| **클로드 코드** | 내 컴퓨터 안에서 일하는 클로드. 파일도 만들고 프로그램도 실행함 | 웹 클로드가 '상담원'이라면 이건 **집에 온 기사님** |
| **프롬프트** | AI에게 주는 지시문 | 심부름 쪽지 |
| **임시저장** | 아직 공개 안 된 상태로 저장해 두는 것 | 냉장고에 넣어둔 반찬 (아직 손님상에 안 올림) |

> 💬 **다 못 외워도 됩니다.** 뒤에 나올 딱 하나의 규칙만 기억하면 돼요. (PART 4-3)

## PART 3. 시작 전에 꼭 알고 가기

### 3-1. 준비물

| 준비물 | 돈이 드나 | 설명 |
| --- | --- | --- |
| Node.js | **무료** | 밑바탕 프로그램 |
| 클로드 코드 | 프로그램 자체는 **무료** | 설치는 공짜 |
| **클로드 유료 구독 (Pro 이상)** | **유료** | 이게 있어야 클로드 코드가 돌아감 |
| 네이버 계정 | 무료 | 이미 있는 블로그 계정 |

### 3-2. 돈 이야기 — 정확히 알고 시작하세요

| 궁금한 점 | 답 |
| --- | --- |
| API 요금 따로 나가나요? | **안 나갑니다.** 구독에 포함된 사용량으로만 돕니다 |
| 한 번 만들면 끝인가요? | ❌ 아닙니다. **글 쓸 때마다 AI가 일하는 구조**라 구독을 유지해야 합니다 |
| 구독을 끊으면요? | 만들어 둔 파일은 컴퓨터에 남지만, 글 자동 작성은 멈춥니다. 다시 구독하면 이어서 쓸 수 있어요 |
| 어떤 모델을 쓰나요? | 상위 모델(Opus 등)은 글이 좋은 대신 사용량을 빨리 씁니다. **글쓰기만 상위 모델로** 돌리는 게 가성비 요령 |

### 3-3. ⚠️ 반드시 지켜야 할 것

> **임시저장 자동화는 네이버 약관상 '회색지대'입니다.**
> 확실히 금지도 아니지만 확실히 허용도 아닌 영역이라는 뜻이에요. 그래서 **반드시 본인 계정으로, 하루 1~2건 수준으로만** 쓰세요. 남의 계정에 쓰거나 하루에 수십 건씩 돌리면 계정이 위험해집니다.

### 3-4. 웹 클로드로는 안 되나요?

| | 글 생성 | 네이버 임시저장 자동화 |
| --- | --- | --- |
| 클로드 웹 '프로젝트' | ⭕ 가능 | ❌ 불가능 |
| **클로드 코드** | ⭕ 가능 | ⭕ 가능 |

임시저장 자동화는 **내 컴퓨터에서 프로그램을 실행**해야 하므로 클로드 코드가 필요합니다.

## PART 4. STEP 0 — 설치 (처음 한 번만)

> 이미 Node.js와 클로드 코드가 깔려 있으면 건너뛰세요.
> 설치가 어려우면 **클로드 코드만 열고 "Node.js 설치해 줘"라고 부탁**해도 됩니다.

### 4-1. 순서대로 따라 하기

**① Node.js 설치**

1. 인터넷 주소창에 `nodejs.org` 입력
2. **LTS**라고 쓰인 버튼 클릭해서 내려받기
3. 내려받은 파일 실행 → **계속 "다음"만 누르면 끝**

**② 터미널 열기**

바탕화면이나 아무 폴더의 **빈 공간에서 마우스 오른쪽 버튼** 클릭 → **"터미널에서 열기"** 선택.

> 이 메뉴가 안 보이면 시작 메뉴에서 **PowerShell**을 검색해서 여세요.

**③ 잘 깔렸는지 확인**

까만 창에 아래를 입력하고 엔터.

```
node -v
```

`v20.11.0` 같은 **숫자가 나오면 성공**입니다.

**④ 클로드 코드 설치**

같은 창에 아래를 입력하고 엔터.

```
npm install -g @anthropic-ai/claude-code
```

⚠️ 설치가 끝나면 **까만 창을 닫았다가 다시 여세요.** (안 그러면 다음 단계에서 "그런 명령 없다"고 나옵니다)

**⑤ 로그인**

새로 연 창에 아래를 입력.

```
claude
```

처음 실행하면 화면 색깔(테마)을 고르라고 하고, 그다음 로그인 화면이 나옵니다. **유료 구독 중인 클로드 계정으로 로그인**하세요.

> 이 로그인 덕분에 구독 사용량이 연결돼서 **API 요금이 따로 안 나가는 겁니다.**

### 4-2. 설치 체크리스트

| 확인 | ⬜ |
| --- | --- |
| `node -v` 했더니 숫자가 나왔다 | ⬜ |
| 클로드 코드 설치 명령을 실행했다 | ⬜ |
| 까만 창을 닫았다 다시 열었다 | ⬜ |
| `claude` 입력하니 실행됐다 | ⬜ |
| 유료 구독 계정으로 로그인했다 | ⬜ |

### 4-3. ⭐ 이 강의의 단 하나의 규칙

> **아래 단계를 외울 필요 없습니다. 뭐가 됐든 막히면 클로드 코드 채팅창에 그냥 물어보세요.**
>
> 설치가 안 돼도, 오류가 떠도, 다음에 뭘 해야 할지 모르겠어도 — **"지금 이런 상황인데 어떻게 해?"**라고 치면 됩니다.
>
> 툴을 만드는 것도, 고치는 것도, 사용법을 알려 주는 것도 **전부 같은 AI**가 합니다. 이 강의 자료는 지도일 뿐이고, **운전은 AI가 해요.** AI가 뭔가를 추천하면 그대로 따라가는 게 기본값으로 맞습니다.

### STEP 3. 클로드 코드 실행 & 모델 고르기

1. **새 폴더를 하나 만듭니다.** (예: 바탕화면에 `블로그툴`)
2. 그 폴더 안 빈 공간에서 오른쪽 클릭 → 터미널에서 열기
3. `claude` 입력
4. `/model` 입력해서 모델 확인

**모델 고르는 요령**

| 언제 | 어떤 모델 |
| --- | --- |
| 툴을 처음 만들 때, 평소 글 쓸 때 | **가장 상위 모델(Opus 등)** — 말맛과 후킹 품질이 여기서 갈립니다 |
| 트렌드 분석, 오류 수정 같은 기계적인 일 | Sonnet으로 충분 — 사용량 아끼는 요령 |

### STEP 4. 계획 모드로 붙여넣기

붙여넣기 **전에** `Shift + Tab`을 **두 번** 눌러 **plan mode(계획 모드)**로 바꾸세요.

> 🤔 **계획 모드가 뭐예요?**
> AI가 바로 만들기 시작하지 않고, **먼저 나에게 질문하고 전체 제작 계획을 보여 주는 모드**입니다. 집을 짓기 전에 설계도를 먼저 보여 주는 것과 같아요.

계획을 읽어 보고 이상한 부분이 없으면 승인합니다. 이렇게 하면 중간에 엉뚱한 걸 만들어서 다시 하는 일이 없어져요.

### STEP 5. 자동 모드로 바꾸고 따라가기

계획을 승인한 뒤 `Shift + Tab`을 **한 번** 눌러 **auto-accept(자동 승인) 모드**로 바꿉니다. 그러면 파일 만들 때마다 묻지 않고 알아서 끝까지 만듭니다.

이후는 AI가 안내하는 순서를 그대로 따라 하면 됩니다.

1. `npm install` (필요한 부품 내려받기)
2. **네이버 로그인 1회** — 세션만 저장되고 **비밀번호는 저장되지 않습니다**
3. 첫 테스트 글 검수

> 🛡️ 자동 모드여도 **임시저장 전 검수 확인은 항상 채팅으로 물어봅니다.** 이건 안전장치라 꺼지지 않아요.

## PART 6. 완성한 뒤 평소 사용법 — 딱 3단계

**① 사진을 폴더에 넣는다**

```
input/photos/
```

**② 채팅에 한 줄 입력한다**

```
/write 서면 ○○식당, 내돈내산, 웨이팅 20분인데 갈비찜이 미쳤음
```

**③ 초안 확인 → 승인 → 네이버 "저장 글"에서 발행**

### 알아 두면 좋은 명령 4개

| 명령 | 하는 일 |
| --- | --- |
| `/write` | 사진 + 메모로 글 초안 만들기 |
| `/learn-style` | 잘 쓴 블로그 글을 붙여넣으면 **말투·구성·심리 전략을 학습** |
| `/analyze-trends` | 글자 수·사진 수·제목 구조 같은 **세팅값을 뽑아 저장** |
| `/setup-login` | 네이버 로그인이 풀렸을 때 다시 로그인 |

> 💡 `/learn-style`은 문장을 베끼는 게 아니라 **구조만 뽑아냅니다.** 그래서 유사문서 위험이 없어요.

## PART 7. 자주 막히는 지점 (실제로 다 겪는 것들)

| 화면에 뜨는 말 | 왜 그런가 | 어떻게 하나 |
| --- | --- | --- |
| "이 시스템에서 스크립트를 실행할 수 없으므로…" | 윈도우 보안 설정 문제 | 터미널에 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` 입력 후 `Y`. **한 번만** 하면 됨 |
| "claude 용어가 인식되지 않습니다" | 설치 직후라서 | 터미널을 **닫았다가 다시 열면** 인식됨 |
| "'&&' 토큰은 올바른 문 구분 기호가 아닙니다" | 구형 PowerShell은 명령 이어붙이기가 안 됨 | 명령을 **한 줄씩 따로** 실행 |
| 네이버 로그인이 풀렸을 때 | 세션 만료 | 채팅에 `/setup-login` 입력. 패스키 로그인도 됨 |
| **그 밖의 모든 오류** | — | **오류 메시지를 그대로 복사해서 클로드 코드 채팅에 붙여넣기** |

> 이게 이 방식의 진짜 장점입니다. **도구를 만든 AI가 옆에 있으니 수리도 알아서 해 줍니다.**

## PART 8. 꼭 지켜야 할 것 & 자주 묻는 질문

### 8-1. ⚠️ 안전 수칙 5가지

**1. 발행은 반드시 사람이.** 임시저장까지만 자동입니다. 이건 일부러 막아 둔 안전장치예요.

**2. 협찬을 받았으면 반드시 표시하세요.** 공정거래위원회 표시광고법 사항이라 **생략할 수 없습니다.** 협찬 글에 "내돈내산", "광고 아님" 같은 **거짓 표현을 쓰면 위법**입니다. 툴도 매번 협찬 여부를 물어보게 만들어져 있어요.

**3. 하루 1~2건만.** 브라우저 자동화는 네이버 약관상 회색지대입니다. 본인 계정으로만 쓰세요.

**4. `naver-profile/` 폴더는 절대 남에게 주지 마세요.** 여기에 내 로그인 세션이 들어 있습니다.

**5. 사실을 지어내지 않습니다.** 사진과 내가 준 정보에서 확인된 것만 씁니다. 확인 안 된 건 AI가 나에게 되물어보게 설계돼 있어요.

### 8-2. 자주 묻는 질문

**Q. 사진만 넣으면 되나요?**
거의 그렇습니다. 사진에서 읽을 수 있는 것(간판, 메뉴판, 가격)은 AI가 알아서 뽑아냅니다. 사진에 없는 정보(위치, 협찬 여부, 내 감상)만 **한 줄 메모**로 주세요. 이 한 줄을 빼먹으면 AI가 지어내는 대신 **되물어보게** 만들어져 있습니다.

**Q. 잘 쓴 블로그 글을 따라 하게 할 수 있나요?**
네, 이게 핵심 기능입니다. `/learn-style`에 붙여넣으면 말투·구성을 배우고, `/analyze-trends`에 주면 글자 수·사진 수 같은 설정값을 저장합니다.

**Q. 알아서 발행까지 해 주나요?**
아니요, 일부러 막아 놨습니다. 임시저장까지만 하고, 저장된 글을 초안과 **글자 단위로 대조하는 검증**까지 거칩니다.

**Q. 쓸수록 똑똑해지나요?**
네. 배운 스타일, 트렌드 설정, 심지어 오류 해결 기록까지 전부 파일로 남아서 다음에 이어집니다. **쓸수록 내 블로그에 맞는 도구가 됩니다.**

**Q. 구독을 해지하면요?**
만들어 둔 툴과 학습 데이터는 내 컴퓨터에 그대로 남습니다. 다시 구독하면 이어서 바로 쓸 수 있어요.

### 8-3. ⭐ 품질은 내가 주는 정보에 비례합니다

이 프롬프트는 **어떤 분야에도 쓸 수 있는 범용 설계도**입니다. 바꿔 말하면, 붙여넣기만 하면 나오는 건 "평균적인 툴"이에요.

| 이렇게 하면 좋아집니다 | 왜 |
| --- | --- |
| AI가 질문할 때 **성의껏** 답하기 | 경력, 취급 품목, 단골 유형, 자주 받는 질문, 내 말버릇까지 — 구체적일수록 글이 좋아집니다 |
| 내 분야 상위노출 글을 꾸준히 학습시키기 | `/learn-style`, `/analyze-trends`에 계속 넣어주세요. **만들자마자보다 한 달 쓴 후가 확연히 다릅니다** |
| 초안을 보고 말투·구성 교정해 주기 | 그 피드백이 파일로 쌓여 다음 글에 반영됩니다 |

> 🌱 **도구를 "키우는" 감각으로 쓰세요.** 첫 글부터 완벽할 수는 없습니다.

### 8-4. 마지막으로

결과는 사람마다 다릅니다. 입력한 정보의 양과 질, 학습시킨 참고 글, 사용한 모델, 그리고 네이버 에디터·알고리즘 변화에 따라 결과물과 동작 여부가 달라질 수 있어요.

**상위노출과 수익을 보장하는 도구가 아니라, 꾸준한 발행을 돕는 도구입니다. 발행 전 최종 확인과 글에 대한 책임은 항상 작성자 본인에게 있습니다.**

## 절대 규칙

1. API 키 사용 금지 — 모든 AI 작업은 Claude Code 세션 안에서 (구독 토큰만 소모, claude -p 지원).
2. 발행 금지 — 임시저장까지만. 발행은 항상 사람이. 태그 입력을 위해 발행 패널을 열어야 하므로, 에디터 로드 직후 캡처 단계 클릭 리스너로 진짜 발행 버튼(button[data-testid="seOnePublishBtn"]) 클릭을 원천 차단하는 가드(installPublishGuard)를 스크립트에 반드시 넣어 이 규칙을 코드로도 보장한다. 어떤 경우에도 이 가드를 제거하지 않는다.
3. 사실 지어내기 금지 — profile.md와 사진에서 확인된 것만. 확인 안 된 정보는 사용자에게 묻는다.
3-1. 협찬 처리(공정위 표시광고법 — 생략 불가): /write마다 협찬·체험단 여부를 반드시 확인하고(메모에 없으면 질문), 협찬이면 data/sponsored-disclosure.md의 대가 유형별 표기 문구를 글 상단 첫 블록에 기본 포함한다(업체 지정 문구가 있으면 그것이 우선, quote가 아닌 일반 text 블록으로). "내돈내산"·"광고 아님" 같은 거짓 부인 표현은 위법이므로 협찬 글에 쓰지 않는다.
4. 소재는 고객 사례가 아니어도 된다(자사 장비·일상 소재 가능). 단 서사를 지어내지 말고 정직하게 자기 사례임을 밝히고 쓴다.
5. 학습 데이터 자동 수집 금지 — 사용자가 제공한 글로만 trends/style-profile 갱신.
6. 초안은 사용자 승인 후에만 임시저장.

## 글쓰기 공식 (실전 검증됨)

- 키워드: 메인 1개(지역명 포함, 제목 앞쪽·첫 문단·마지막 문단 배치, 본문 5~7회, 띄어쓰기까지 검색어와 동일하게 1회 이상) + 서브 2~3개(소제목 배치).
- 페르소나 설계 필수: 메인 키워드를 검색하는 1명을 구체적으로 정의(지역·나이·직책·상황·감정)하고 그 사람에게 말 걸듯 쓴다. 초안 검수 시 페르소나도 보고.
- 첫 문단 Yes-set: 첫 2~3문장에서 페르소나의 상황·감정을 적중시켜 "맞아, 내 얘기다"를 연속 유도 + 결론 예고. 예: "발전기 시동 버튼을 눌렀는데 아무 반응이 없으셨죠. 점검 날짜는 다가오는데 막막하실 겁니다. 결론부터 말씀드리면, 열에 아홉은 엔진 문제가 아닙니다."
- 둘째 문단 권위 한 줄: authority-lines.md에서 골라 변형해 툭 던지듯. 자랑·업체명·연락처 금지. 정보성 글엔 "솔직함형"(예: "업체 입장에선 이런 글 쓰면 안 되는데, 자꾸 당하는 분들이 계셔서 씁니다")이 가장 강력.
- 후킹 패턴은 매번 다르게 선택: 손실 회피형 / 현장 몰입형 / 반전형 / 공감형.
- 홍보 냄새 제거: 정보성 글 본문에 업체명 금지(CTA에서만 1회), 연락처는 글 전체 1회, 업체명 본문 3회 이내.
- 가독성(모바일 기준): 한 문장 = 한 줄, 한 블록 3~5줄, 리듬 파괴 장치(인용구/구분선/사진/소제목)를 300~400자마다, 핵심 문장은 인용구로 글당 2~4개. 텍스트만 500자 연속이면 실패작. 표는 "✔ 항목 — 내용" 체크리스트로 대체.
- 기본 세팅: 1,800~2,500자(정보성 3,000자까지), 사진 10~15장(장당 텍스트 2~4문단), 제목 25~32자. 유사문서·저품질 회피(도입 패턴 매번 변경, 사진 재사용 금지, 외부링크 1개, 광고 어휘·제목 특수문자 금지).
- 업종별 필수 정보 체크리스트: 제작 인터뷰에서 "검색자가 원하는 실측 정보 목록"을 업종에 맞게 정의해 CLAUDE.md에 박고, 초안 검수 때 항목별 대조한다. (예 — 맛집: 교통·주차·웨이팅·좌석 + 먹은 메뉴마다 메뉴명·가격·맛·팁 4종 세트 + 단점 1개 포함 총평. 확인 안 된 항목은 지어내지 말고 묻거나 뺀다.)
- 발행 체크리스트(임시저장 후 안내): 태그 5~10개·지도·동영상·소제목 서식은 스크립트가 자동 처리하므로, 실행 로그의 "자동 처리 결과" 블록을 확인해 실패 항목만 수동 안내한다. 넘어서 안내할 수동 항목: 타겟 활동 시간대 발행, 발행 후 24시간 수정 금지, 주 2~3회 주기(하루 2건 이상 금지), 협찬 표기 육안 확인.

## 사진·영상 처리

- 사진은 분석한 스토리 순서로 배치한다 (파일 순서 아님). 캡션(caption)에도 키워드 1~2회 자연 배치 — 전체 사진의 절반 정도만.
- **개인정보 모자이크 (scripts/mosaic.js, 필수)**: 사진에서 식별 가능한 타인 얼굴·차량 번호판·전화번호 등을 발견하면: ① 문제 영역 좌표(0~1 상대값, 상하좌우 15% 여유)를 담은 spec을 drafts/에 JSON으로 저장 ② mosaic.js 실행 — 처리본은 input/photos/_mosaic/에 생성되며 원본은 절대 덮어쓰지 않는다 ③ 처리본을 Read로 열어 실제로 가려졌는지 확인, 덜 가려졌으면 좌표를 키워 재실행 ④ 초안에는 처리본 경로 사용. 구현 함정 둘: 좌표 기준은 반드시 EXIF 회전 보정 후(보이는 화면 기준)로 잡을 것, sharp 사용 시 한 파이프라인에 resize는 1회만 적용되므로 축소→버퍼→확대(nearest)로 2단계 분리할 것. 검수 보고에 처리 내역(몇 장·몇 영역·사유)을 포함하고, 화자 본인 얼굴도 기본은 모자이크(공개를 명시한 경우만 예외).
- **동영상 자동 첨부**: input/videos/에 영상이 있으면 초안의 video 필드에 넣는다. 항상 첫 text 블록 직후에 삽입되며(D.I.A. 가산 요소), 영상 제목은 필수·40자 제한(video.title > 글 제목 > 기본값 순). 업로드에 수 분 걸릴 수 있다.

## 자가 검증 원칙 (이 툴의 품질 엔진 — 가장 중요)

모든 단계에서 "했다"가 아니라 "됐는지 확인했다"로 끝내라:
1. 이중 검증: 임시저장 후 (a) 스크린샷 + (b) 에디터 문서의 제목·본문 전체 텍스트를 덤프 파일로 추출해 초안과 전문 대조한다. 스크린샷은 화면 상단만 보이므로 텍스트 덤프가 본검증이다. 불일치하면 성공 보고 금지 — 원인을 찾아 수정한다.
2. 셀렉터가 실패하면 추측으로 고치지 말고, 실제 DOM을 검사하는 일회용 스크립트를 만들어 실측 후 수정한다.
3. 문제를 해결하면 원인과 해결책을 CLAUDE.md에 기록하고, 안정 버전 스크립트를 .working.js로 백업한다. 기억할 가치가 있는 건 전부 파일로 — 다음 세션은 대화를 기억하지 못한다.
4. 초안 검수 시 자가 질문: "모바일에서 인용구와 소제목만 훑어도 핵심이 전달되는가?"

## 실측 지식 (수십 시간 디버깅으로 확인 — 그대로 반영할 것)

- 본문 셀렉터는 .se-section-text p.se-text-paragraph 로 한정. 제목도 내부적으로 같은 문단 구조(p.se-text-paragraph)를 쓰기 때문에, 범위를 넓게 잡으면 본문 클릭이 제목을 오염시켜 제목이 깨지고 본문 첫 줄이 사라진다. 제목은 .se-title-text.
- **입력 순서는 본문 전체 먼저 → 제목은 맨 마지막** — 제목 직후 본문을 치면 레이스 컨디션으로 섞임이 재현된다. 제목 입력 후 실제 값을 읽어 초안과 비교하고, 불일치면 전체 선택·삭제 후 재입력. 본문 첫 줄도 저장 전에 앞 10여 자 포함 여부를 검사해 누락이면 맨 앞에 보정 삽입한다.
- 브라우저 뷰포트는 1600×1000 이상으로 — 1400 이하에서는 패널이 열릴 때 속성 툴바가 잘려 서식 버튼 클릭이 불안정해진다.
- 한글은 반드시 keyboard.insertText() — keyboard.type()은 IME 조합이 꼬여 오탈자 발생. 이모지는 별도 호출로 분리 삽입 (함께 넣으면 이모지 뒤 텍스트 유실).
- 인용구/구분선 버튼의 실제 클래스: se-insert-quotation-default-toolbar-button / se-insert-horizontal-line-default-toolbar-button. 추측 클래스명 금지.
- **소제목 서식은 볼드 토글로 하지 말 것** — 스마트에디터에선 선택 영역이 안 잡혀 실패한다. 문단 서식 드롭다운(se-text-format-toolbar-button → "소제목" 옵션)을 쓰면 캐럿만 놓여도 문단 전체에 적용된다. 기본 크기 30은 너무 커서 19(fs19 옵션)로 낮추되, 순서가 핵심: 서식 → 크기 → 텍스트 입력 (입력 후 바꾸면 이미 쓴 글자에 적용 안 됨). 입력 후 다음 문단은 "본문"으로 명시 복귀시키고, 드롭다운 라벨을 다시 읽어 적용 여부를 검증한다.
- text 블록이 연달아 오면 문단이 빈 줄 없이 붙어 렌더링된다 → 다음 블록도 text일 때만 끝에서 Enter를 한 번 더 누른다. 사진·소제목·인용구 앞은 에디터가 자체 여백을 준다.
- **태그 자동 입력**: 우상단 발행 버튼으로 패널을 열고 input#tag-input에 태그마다 입력+Enter로 칩 확정(입력 전 앞의 # 제거, 최대 30개) → Escape로 패널만 닫기 → 그 다음 임시저장. 패널 안에 진짜 발행 버튼이 있으므로 발행 차단 가드(절대 규칙 2)가 전제다. 태그 검증은 태그 영역 텍스트를 #로 쪼개 센다(칩 클래스는 해시가 바뀌므로 의존 금지).
- **지도(플레이스) 자동 첨부**: 지도 툴바 버튼 → 장소명 검색 → 결과가 여러 개면 place.name과 공백 제거 정확 일치 → 부분 포함 → 첫 결과 순으로 선택. 결과 항목의 "추가" 버튼은 hover 전에는 not visible이라 그냥 클릭하면 타임아웃 → 항목 hover 후 클릭(폴백은 DOM 직접 click). "추가" 전까지 확인 버튼은 disabled 상태. 장소 팝업은 Escape로 안 닫힌다 → 반드시 팝업 닫기 버튼 사용. 안 닫으면 dim 레이어가 남아 이후 모든 클릭이 "intercepts pointer events"로 실패한다.
- **동영상 자동 업로드**: 동영상 툴바 버튼 → 업로드 팝업의 "동영상 추가" 버튼이 파일 선택창을 띄운다. 제목 입력 필수(40자 제한). 팝업을 확실히 닫지 않으면 dim 잔류로 이후 클릭 전부 실패 — 닫기 실패 시 DOM에서 강제 제거 폴백까지 넣는다.
- 자동화 결과는 실행 로그 마지막에 "자동 처리 결과" 블록으로 항목별(태그/지도/동영상/소제목) 성공 여부를 출력하고, ❗수동 필요로 찍힌 항목만 사용자에게 안내한다.
- **--dry-run 플래그**: 저장 클릭만 생략하는 옵션을 스크립트에 넣는다 — 셀렉터 디버깅 중 "저장 글" 목록에 실패본이 쌓이지 않게. 셀렉터 수정 중엔 항상 이걸로 먼저 돌린다.
- 진입 시 "작성 중인 글" 팝업은 새로 쓰기(.se-popup-button-cancel)로 닫는다. 디버깅 재실행이 반복되면 네이버 "저장 글"에 실패본이 쌓이니 완료 보고 시 사용자에게 직접 정리 안내(자동 삭제 금지 — 파괴적 작업).
- 네이버 블로그 본문은 WebFetch 불가(도메인 차단)일 수 있다 — 재시도 말고 바로 사용자에게 본문 붙여넣기를 요청할 것.
- 셀렉터는 네이버가 수시로 바꾼다. 실패 시 probe 스크립트로 실제 DOM을 떠서 실측 후 수정하고, 3회 실패 시 수동 붙여넣기용 원고를 출력할 것.
